Remote ID sensor user guide

This guide is for you if you have a finished unit and want to know what its Remote ID sensor does. The unit's user guide covers the whole unit. This page covers one of its two sensors.

Applies to Remote ID sensor firmware 0.7.3.

What the sensor listens for

The Remote ID sensor listens for three kinds of signal:

  • Remote ID, the identity that many aircraft must broadcast by law over Wi-Fi or Bluetooth.
  • Wi-Fi drones, which a pilot flies from a phone over an ordinary Wi-Fi network.
  • Control links at 868 MHz, the long-range radio control that ExpressLRS uses.

The sensor only receives. It doesn't transmit on any radio.

What the sensor can't detect

The sensor can't detect these signals:

  • Most DJI aircraft, unless they broadcast Remote ID. DJI's own link between aircraft and controller, OcuSync, isn't Wi-Fi, and this sensor has no receiver for it. The unit's RF sensor might detect its energy.
  • Older DJI models with Enhanced Wi-Fi, such as the Mavic Mini, the Mini SE, and the 2018 Mavic Air. Their channels are too narrow for an ordinary Wi-Fi receiver. For the list of models, see the vendor hints.
  • A Wi-Fi drone whose network name the sensor doesn't know, or one that its owner renamed. For the names it knows, see the vendor hints.
  • Wi-Fi on the 5 GHz channels 52 to 144. The sensor visits channels 1 to 13, 36 to 48, and 149 to 165.
  • Control links that don't use LoRa, such as Crossfire's fast mode, and anything in the 915 MHz band. The project doesn't use the 915 MHz band in Europe.
  • An aircraft that sends nothing, or one that flies a stored route with its radio off.

The sensor listens on one Wi-Fi channel at a time, then for Bluetooth, in turn. A short broadcast can fall into a gap, so if the sensor reports nothing, something might still be there.

Get started

  1. Before you switch the unit on, connect both antennas. Connect the 2.4/5.8 GHz antenna to the small connector on the XIAO board. Connect the 868 MHz antenna to the connector on the Wio-SX1262 board under it. Without the antennas, the sensor appears to work but receives almost nothing.

  2. Switch the unit on. The sensor gets its power from the master and starts with it.

  3. On the master, check that the sensor is running:

    • At the lower left of the HOME screen, the light shows a green dot and SCANNING. A yellow warning sign means that a sensor isn't running.
    • Tap PORTS. One port shows RID SENSOR and UP. It doesn't matter which port.

  4. If you can see the sensor board, check its yellow light:

    Light Meaning
    One short flash every 2 seconds Running, nothing detected
    Even blink, once a second A Wi-Fi name, a Wi-Fi link, or a DJI element in the last 5 seconds
    On without blinking A Remote ID decoded in the last 5 seconds
    Fast blink A radio fault

  5. Optional: If you have a Remote ID source, test the sensor with it. Switch on an aircraft that broadcasts Remote ID nearby, or use a phone app that sends a test Remote ID. The master lists a row tagged RID with the name from the broadcast. With a source on Wi-Fi channel 6, this takes 2 to 3 seconds.

What the sensor reports

The master shows each report as a row. The tag is the word in the row's box.

Tag What the sensor detected What it means
RID A decoded Remote ID An aircraft, or its controller, broadcasts who and where it is. The master shows the name and position that the broadcast claims, without checking them
DJI A Wi-Fi frame with DJI's own element An older Wi-Fi DJI device is nearby. The sensor recognizes the element but doesn't decode it
LINK Data flowing both ways on a network with a drone's name or a drone maker's address Something is flown or operated over Wi-Fi
WAIR An aircraft's own network, announced by the aircraft under a name the sensor knows An aircraft is switched on nearby. This raises an alert by itself
WIFI A network name or an address that belongs to a drone maker A hint. The master shows it as a notice, not an alert
SUB, control LoRa packets like those ExpressLRS sends, on the watched 868 MHz channel, for several seconds in a row A long-range control link is probably on the air
SUB, bursts Short, unrecognized transmissions on the 868 MHz channel A notice. Meters, alarms, and other sensors share this band

A LINK row can also come from a camera, a controller that's being set up, or a file download from an aircraft that has landed. A WIFI row can come from a drone, its controller, or anyone who named a hotspot DJI-something. Other LoRa users of the band can raise a SUB control row for a few seconds.

The signal strength beside a row shows how strongly this sensor received the signal. It doesn't show distance.

For how the master turns these reports into alerts, see the unit guide's signal types and alert levels.

Update the firmware

You can update the sensor through its own USB-C port. You can also use the firmware page, which flashes this sensor through its own USB-C port without resetting it. The firmware page hasn't been tested on a real sensor.

Warning

Don't let a tool reset this board. The chip is a revision 1.0 ESP32-C5. When a tool resets it in the usual way, through the serial port's control lines, the chip can stop responding, with its USB port dead, until you remove all power. Always keep --before no-reset --after watchdog-reset in the esptool command. Don't press the board's buttons to start its loader.

To update the sensor from the command line, you need the three image files of a release (bootloader.bin, partition-table.bin, and c5_drone_detector.bin) and Python with esptool and pyserial. The commands in this section haven't been tested from a laptop in exactly this form.

  1. Connect a USB cable from your computer to the sensor's USB-C port, not the master's.

  2. Find the sensor's port name. On macOS, run ls /dev/cu.usbmodem*. On Linux, run ls /dev/ttyACM*. The steps use /dev/cu.usbmodem1101 as an example.

  3. Close any program that uses the port, such as a serial monitor.

  4. Start the sensor's loader:

    python3 -c 'import serial,sys; serial.Serial(sys.argv[1],115200).write(b"\n{\"cmd\":\"boot\",\"id\":4000000002,\"mode\":\"download\"}\n")' /dev/cu.usbmodem1101

    Opening a serial port can change its control lines on some computers and drivers. If the sensor stops responding, remove all power sources, including the battery, then reconnect them.

  5. Wait 5 seconds, then write the images:

    python3 -m esptool --chip esp32c5 --port /dev/cu.usbmodem1101 --baud 460800 \
  --before no-reset --after watchdog-reset write-flash \
  --flash-mode dio --flash-freq 80m --flash-size 8MB \
  0x2000 bootloader.bin 0x8000 partition-table.bin 0x10000 c5_drone_detector.bin

The sensor restarts automatically. On the master, the PORTS screen shows the sensor as UP with the new firmware version.

If the sensor's USB port is dead after a flash, the chip has stopped in its loader. Remove every power source, including the battery, and then reconnect them.

Use the sensor alone on USB

The sensor works without the master. When you power it from a computer's USB port, it starts listening after 3 seconds. It sends one line of JSON for each signal it detects, and a status line every 5 seconds. To read these lines in a browser on your own computer, use the viewer. The viewer doesn't upload anything.

Check the 868 MHz radio board

To check that the Wio-SX1262 board is seated and responds, connect the sensor to your computer over USB, and then send it this line:

python3 -c 'import serial,sys,time; s=serial.Serial(sys.argv[1],115200,timeout=2); s.write(b"\n{\"cmd\":\"sg_probe\",\"id\":4000000003}\n"); time.sleep(1); print(s.read(4000).decode(errors="replace"))' /dev/cu.usbmodem1101

If the answer contains "present":true, the radio responds. If it contains false, the board has lost contact. A board that's pressed on without solder might not respond.

In the unit, the master shows the same thing. A sensor with a working 868 MHz radio reports its level on that band every second.

Troubleshooting

What you see Likely cause What to do
The RID SENSOR port turns red for a few seconds, then green A radio fault. The sensor switched its receivers off and started them again automatically after 2 seconds Nothing. If it happens often, note the time and report it
The RID SENSOR port stays red The fault didn't clear, or the master can't communicate with this firmware Switch the unit off and on. If the port stays red, update the sensor's firmware
The port shows -- or stays gray The sensor has no power, or the two wires between the sensor and the master are loose or crossed Check the wiring against the wiring guide
No 868 MHz signal is ever listed, and the phone shows reduced coverage The Wio-SX1262 board doesn't respond Check the 868 MHz radio board. The sensor continues to detect Remote ID during that time
SUB rows appear and disappear with no aircraft nearby Another user of the band is nearby Calibrate the unit at that place, as the unit guide's calibration section describes
The sensor is dark and silent while the unit charges The sensor sleeps when the master is off and no computer is connected to its USB port. This saves the battery Switch the unit on
The sensor's USB port is dead after a flash The chip stopped in its loader Remove every power source, including the battery, then reconnect them
A Remote ID source nearby isn't listed The broadcast came on a channel, or at a moment, that the sensor wasn't listening to. Or it uses a 5 GHz channel that the sensor visits only every other second Wait 30 seconds. Broadcasts repeat, and the sensor returns to each channel about once a second

Known limitations

  • Nothing on this page has been measured with a real aircraft in flight. One Wi-Fi drone has been tested indoors, as described in the next section.
  • The yellow light's patterns come from the code. Nobody has checked them by eye.
  • The two update commands haven't been run from a laptop in exactly this form.
  • Sleep and wake are built but haven't been tested on hardware.
  • The DJI row hasn't been tested over the air.
